# Mask-Aware Teacher and BC Alignment Design

## Objective

Remove the behavioral-target discontinuity between Randomized Strong BC and
subsequent PPO. The current BC data records Teacher source hash
`ec8c288b...`, while PPO uses the mask-aware Teacher at `d1dea222...`. The new
pipeline must train BC from demonstrations generated by the exact Teacher
implementation that PPO will supervise against.

This change stops after producing and validating an aligned BC artifact. It
does not start another PPO run.

## Preserved artifacts

The existing demonstration data, BC checkpoint, Randomized 200k PPO, failed 1M
run, and public Showcase remain immutable. Aligned artifacts use independent
paths:

- data: `data/generated/extraction-randomized-mask-aware-v2/`;
- BC: `runs/extraction-randomized/strong-bc-mask-aware-v2/`;
- reports: `reports/extraction/mask-aware-bc-alignment/`.

## Teacher ceiling gate

Before generating a large dataset, evaluate the current mask-aware privileged
Teacher in closed loop on 120 paired randomized-validation episodes, balanced
across learner side and Strong, Aggressive, Defensive, and Explorer opponents.
This evaluation is training/validation-only and must report
`test_cases_accessed=false`.

Proceed only when:

- overall extraction rate is at least 85%;
- Strong and Aggressive opponent extraction rates are each at least 70%;
- protocol inconsistencies equal zero.

If the Teacher fails, fix the Teacher and repeat this gate. Do not generate BC
data from a demonstrator whose closed-loop ceiling is already inadequate.

## Aligned demonstration and BC training

After the Teacher gate passes:

1. Generate 100,000 training and 20,000 validation transitions with the
   current mask-aware Teacher.
2. Keep the existing randomized train/validation case split, fair Actor
   observations, action space, model, BC optimizer, and update budget fixed.
3. Train BC from scratch in the independent output directory.
4. Select the offline checkpoint by validation loss as before, but do not
   promote it based on action accuracy alone.

Keeping the previous data budget and BC hyperparameters isolates Teacher
alignment as the changed variable.

## Teacher identity contract

Teacher identity becomes an enforced lineage field rather than an informal
file hash:

- train and validation manifests must contain the same
  `teacher_implementation_sha256`;
- BC training rejects mismatched manifest Teacher hashes;
- BC summary and checkpoint lineage record that hash;
- any future mask-aware PPO configuration requires the BC lineage hash to
  equal the current `extraction_teacher_sha256()` before loading weights;
- legacy artifacts without the field remain readable for evaluation, but may
  not enter the new aligned PPO path.

This guard must fail before environment startup or optimizer creation.

## BC closed-loop gate

Evaluate the selected BC checkpoint on the same 120 paired randomized cases
used for the Teacher ceiling. The aligned BC is accepted only when:

- overall extraction rate is at least 70%;
- extraction against Strong is at least 50%;
- extraction against Aggressive is at least 50%;
- protocol inconsistencies and Actor privilege violations equal zero;
- `test_cases_accessed=false`.

The report also records win rate, death rate, extracted-value advantage, and
paired bootstrap intervals. Failure means the target mismatch is fixed at the
lineage level, but the BC artifact is not yet strong enough for PPO; no PPO run
is launched.

## Verification and deliverables

Verification covers:

- unit tests for manifest mismatch rejection, checkpoint lineage persistence,
  and PPO preflight rejection;
- a small generation/BC smoke proving the new paths and hashes;
- the 120-episode Teacher ceiling report;
- completed 100k/20k aligned manifests and BC summary;
- the 120-episode BC closed-loop report;
- one machine-readable alignment decision identifying the Teacher hash, data
  hashes, BC checkpoint hash, every gate, and whether PPO is authorized.

No official test cases are accessed, and no public Strong checkpoint is
replaced in this scope.
